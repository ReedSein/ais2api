# 实施状态

状态截至 2026-10-20。阶段以原计划的进入条件验收，不能仅按代码是否存在判断完成。

| 阶段 | 已实现或验证 | 仍需完成的进入条件 |
|---|---|---|
| M0 工程与合同 | C++20/CMake、锁定清单、配置及扩展 schema、独立协议测试；Windows 与 Debian 13 / WSL 2 GCC/Clang 验证通过 | Ubuntu/Termux 实际编译与离线测试 |
| M1 最小真实链路 | 原生浏览器管理/CDP、独立上下文、导入、页面桥接；Windows 安装及未登录错误路径实测 | 有效账号的单轮和多轮真实生成 |
| M2 流式与限额 | 增量解析、SSE、信用确认、事件唤醒、断连取消、队列及对象限制；离线 HTTP 回归通过 | 真实上游与慢客户端、媒体、断连故障结合验证 |
| M3 完整生成能力 | 双协议、签名、函数值、工具、生图及内联多模态的映射和往返测试 | 对应权限账号的完整能力矩阵；尚无可靠协议映射的参数保留明确错误 |
| M4 账号运行管理 | CLI/IPC、凭据更新、冷却、密钥、工具注册表、统计、SQLite；离线与 CLI 回归通过 | 真实账号切换、浏览器崩溃、长期凭据及重启恢复验证；多驻留上下文调度尚未实现 |
| M5 三端环境 | Windows 原生准备及额外 Debian 13 / WSL 2 自动准备实测；三端构建与环境准备入口、升级目录切换与回退实现 | Ubuntu 和真实 Android Termux 的干净安装、升级失败和真实调用 |
| M6 稳定与发布 | Windows 开发包、校验及验包工具、固定负载回放、CI 定义 | 两小时资格测试、浏览器测量、原项目同机对照、三端完整发布门槛 |

目前交付的是可构建的开发实现，不能称为完整重写验收通过。细节见 [验证记录](validation.md) 和 [协议支持边界](protocol.md)。没有添加 Web 管理页面；按后续需求增加了由独立密钥启用的 userscript Cookie 导入接口，其他管理操作仍使用 CLI。
