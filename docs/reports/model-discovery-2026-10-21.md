# 模型发现与账号身份等待修复

验证日期：2026-10-21。Windows 原生后端、CloakBrowser 146.0.7680.177.4，以及 Debian 13 / WSL 2 的调用与离线构建环境。

## 故障与定位

已有账号的 `GET /v1/models` 在本机实际返回 HTTP 401、`identity_mismatch`，一次复现约 8.4 秒。未更换 Cookie、邮箱或账号索引。

独立隔离浏览器复查同一账号时，页面加载过程中最初没有邮箱标识；随后出现的邮箱与保存的预期身份一致，上游 ListModels 返回 HTTP 200。旧实现只等编辑器出现，立即读取邮箱，并把空邮箱与明确不同的账号都归为身份不匹配。这造成了动态账号控件加载时的误判。

模型发现还错误依赖生成初始化：必须先取得编辑框、Run 按钮、GenerateContent 模板及快照服务。页面自身的 ListModels 可以通过 XHR 发送，原桥接只捕获 fetch，可能漏掉已经成功的请求。

## 修复

- 使用独立的身份状态：尚未加载、唯一匹配、明确不同、多个候选。身份等待有 60 秒上限、可取消，明确不同需持续 2 秒才返回 `identity_mismatch`；身份缺失或歧义使用 `identity_unverified`，不当作已确认的账号失效。
- 模型发现只需确认所选账号身份，独立于生成模板；读取缓存前也重新校验账号，切换上下文会清空缓存。
- 同时捕获页面实际发出的 fetch / XHR ListModels，验证并绑定 `auth_user` 后请求上游。没有硬编码 API Key、构造生成请求或返回固定模型表。
- 等待捕获最多 2 秒，上游请求最多 10 秒，响应限制 1 MiB。缺少兼容请求时明确失败，用户显式配置的模型仍标记为 configured。

## 真实复测

Windows 已安装版本更新后，使用原有账号和配置：

| 调用 | 结果 |
|---|---|
| Windows `/v1/models`，服务冷启动 | HTTP 200、41 个模型，约 10.63 秒 |
| Windows `/v1/models`，后续请求 | HTTP 200、41 个模型，source=cache |
| Windows `/v1beta/models` | HTTP 200、41 个模型，source=cache |
| Windows `/v1/models/{id}` | HTTP 200，返回 ID 与请求一致 |
| Debian WSL localhost 调用 `/v1/models` | HTTP 200、41 个模型，source=cache；实际服务为 Windows 进程 |

上述配置中的 configured_models 数量为 0，因此不是配置回退。模型数量是本次账号和上游时点的实测结果，不是保证或固定列表。一次冷启动耗时不作为性能基准。

自动回归覆盖延迟身份、明确错号、歧义拒绝、无生成模板的 XHR 模型发现、槽位冲突、响应限额及超时中止。验证日志仅保留状态、计数、是否匹配和耗时，不保存 Cookie、密钥、邮箱或上游正文。

Windows 为 105 用例、1,599 条断言；Debian GCC 及 Clang ASan/UBSan 为 105 用例、1,591 条断言；网页桥接为 18 项测试。各平台差异来自系统专用断言。重定向或桥接暂不可用会重置连续错号计时，单次身份探测限制为 5 秒，避免用旧观测误判新页面。

该记录证明 Windows 真实账号的模型发现及 WSL 到该服务的调用；不代表 Debian 原生真实账号、内容生成、思考签名、工具调用、多模态或生图已经验收。
